# 组装规则（输入 → 意象 → 提示词）

本文件是 `muse-illustration` 的执行细则，供组装提示词时加载。

## 1. 解析意象

### 输入三类

| 类型 | 例子 | 处理 |
|---|---|---|
| 诗词 / 词句 | 「千里莺啼绿映红，水村山郭酒旗风」 | 逐句抽意象，忠实还原 |
| 意象词 | 「月下孤舟」 | 直接展开为画面元素 |
| 单句灵感 | 「一个人在海边等日落」 | 抽象 → 具象；信息不足时先给意象清单请用户确认 |

### 抽取六个维度

1. **主体** —— 人 / 物（可以是「无主体」的纯风景）
2. **景物** —— 山、水、建筑、植物、天气
3. **动作** —— 动态元素（飞、行、落、浮）
4. **色彩词** —— 原文明确提到的颜色（如「绿映红」）
5. **情绪基调** —— 清雅 / 苍凉 / 热烈 / 孤寂
6. **时空** —— 季节、晨昏、晴雨

### 输出

产出一份「意象清单」，每项映射到画面中的**视觉元素**。映射优先查 `assets/lexicon/imagery.yaml`；查不到则按常识归纳，并把新映射补进词典。

**示例（江南春）**

| 原文意象 | 视觉元素 |
|---|---|
| 千里莺啼 | 小飞鸟剪影，点缀枝头与空中 |
| 绿映红 | 低饱和绿块 + 疏落红点 |
| 水村山郭 | 数座坡顶屋块，临水 |
| 酒旗风 | 细杆 + 小旗块，倾斜示风 |
| 南朝四百八十寺 | 成组深色坡屋顶剪影 |
| 楼台烟雨中 | 深色轮廓 + 纸色留白，罩淡色横带 |

## 2. 风格选择的选项规范

未指定风格时，**用选择框（平台的提问工具）让用户选**，不要替用户决定。选择框的选项构成固定如下。

| 序 | 选项 | 说明 |
|---|---|---|
| 1 | **自动匹配风格（推荐）** | 用户选它 = 授权你按意象清单自行裁定。裁定后说一句理由，直接进入组装，**不再二次追问** |
| 2…n | 库内**每一个**风格 | 标签 = `meta.yaml` 的 `name`；描述 = 一句话特征 + 适配情绪（`mood`） |

### 硬性规则

- **风格清单是活的**：每次现读 `assets/styles/` 目录生成，**不得在 SKILL.md 或本文件里写死风格名**（当前有 3 条，新增一条选择框就多一项）。
- **「自动匹配」是选项，不是默认静默行为**：用户不选它，你就不能替他定。
- **「自动匹配」也不等于静默**：裁定后必须回报「选了哪条 + 为什么」，用户可当场改口。
- 用户说「随便 / 你定 / 都行」→ 直接走自动匹配，**不必再弹一次框**。

### 自动匹配的裁定顺序

1. 用户提示词里是否已含风格线索（「版画」「木刻」「印刷感」…）→ 有就直接命中
2. 意象清单的**景物 / 题材**是否命中该风格 `best_for`
3. **情绪基调**是否命中该风格 `mood`
4. 仍分不出高下 → 把并列的 2 条**都报出来**，各给一句区分点，让用户点一条（不硬选）

### 让选项可读

- 描述里给**区分点**，不要只写风格名。例：「江南春·水印木刻：平涂色块 + 短刻痕，清雅 / 静谧 / 悠远」。
- 需要时用 `assets/cases/images/` 里已采纳的成图当样张辅助说明。

## 3. 组装提示词

### 拼装模板

```
[媒介与风格总述] + [构图与版式] + [背景] + [主体元素（逐个做部件级描述）] + [色彩] + [质感与笔触] + [氛围与留白]
```

再追加负向约束：

```
NEGATIVE: <风格 prompt.negative.txt 的内容>
```

### 原则

- **部件级描述优先**：每个主要物件写清「它被概括成什么形状 / 什么颜色 / 是否用纸色留白」。
- **原文有色彩词时，显式「点出」并要求读得清**：如《忆江南》「日出江花红胜火，春来江水绿如蓝」，在提示词里明确写出这两色并说「让它们读得清」，成图能忠实还原诗眼，而整体仍保持低饱和（2026-10-14 验证有效）。
- **英文撰写提示词**：生图模型对英文遵循度更好。中文输入 → 先抽出意象清单 → 再译为英文提示词。
- **长度适中**：结构化、信息密度高，不堆砌同义词。
- **参考图只借风格**：传入 `ref.jpg` 时，明确写「只借其平涂色块、刻痕与手工印制质感，**不要照抄构图**」。

## 4. 张数与成品形态

### 成品形态 → 尺寸

| 成品形态 | 比例 | size 参数 |
|---|---|---|
| 纯插画（默认竖版立轴） | 2:3 | `1024x1536` |
| 小红书 | ≈3:4 | 用 `1024x1536` 生成后轻微裁切，或在 App 内加留白 |
| 方图 | 1:1 | `1024x1024` |
| 横版 | 3:2 | `1536x1024` |

ImageGen 常用尺寸即 `1024x1024` / `1024x1536` / `1536x1024`，其余比例靠生成后裁切。

### 张数

- **1 张**：省额度，命中即用。
- **2 张**：小幅变体，二选一。
- **4 张**：多变体择优，成本 ×4。适合首次尝试某风格、构图不确定时。

成本提示：**每张约 5-10 积分**，生成前必须告知用户。

## 5. 标题字与本地排版（海报）

生图模型渲染中文字不可靠，**不要在生图提示词里要求写汉字**。

带标题字的海报走两段式：

1. 生成**无字底图**（负面词里加入 `no text, no lettering, no characters`）
2. 用本地渲染（HTML/Canvas 或图像工具）叠上标题字与落款

Phase 1 暂不内置叠字脚本；先用「生成底图 → 在小红书 App 内加文字贴纸」替代。叠字能力列入 Phase 3。

## 6. 归档

用户采纳后，按 `references/style-spec-template.md` 的案例格式，在 `assets/cases/` 追加一条记录（输入 / 意象 / 风格 / 提示词 / 参数 / 成图 / 评价）。这是本 skill 越用越准的关键。

**同时把采纳的成图拷一份进技能**，做成自包含：

```
cp <原始输出路径> assets/cases/images/YYYY-MM-DD-<slug>.jpg
```

案例记录里「成图」指向技能内副本，「原始输出路径」保留原址。这样即使项目里的 `generated-images/` 被清理，技能仍是完整可迁移的。
